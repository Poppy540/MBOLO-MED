# ADR-0001 — Dossier médical au format HL7 FHIR

- **Date :** 2026-09-26
- **Statut :** acceptée (décision du porteur de projet, D-0001)

## Contexte
Il faut un dossier médical interopérable (eGabon-SIS, laboratoires, pharmacies, CNAMGS à terme), extensible et fondé sur un standard international.

## Décision
- HL7 **FHIR R4** (version à confirmer selon eGabon-SIS ; R4 est la plus répandue).
- Ressources principales : Patient, Practitioner, PractitionerRole, Encounter, Observation, Condition, AllergyIntolerance, MedicationRequest, MedicationStatement, Consent, QuestionnaireResponse, Appointment, ServiceRequest, DiagnosticReport, Communication, AuditEvent, Provenance.
- Serveur open source (ex. **HAPI FHIR**) ; authentification SMART on FHIR / OAuth 2.0 ; un client par agent avec des scopes minimaux (voir `secrets/inventaire-cles.md`).
- Un profil national « Mbolo » (Implementation Guide) sera défini, aligné si possible sur eGabon-SIS.

## Conséquences
- Interopérabilité facilitée ; outillage abondant.
- Charge d'exploitation d'un serveur FHIR ; nécessité de profils et de terminologies (CIM-10/CIM-11, LOINC, SNOMED CT selon licences).

Sources : https://hl7.org/fhir/R4/ · https://hapifhir.io/ · https://docs.smarthealthit.org/
